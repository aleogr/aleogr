# As project-apply-database-start-wait-limit, run as the shell runs it with a real clock: the
# file clock makes each sleep 30 count as thirty seconds. A command's waits end when the next one
# would pass seven minutes (13 waits), so the run takes three commands: tries 1 to 14, then the
# continuation plans again and makes tries 15 to 28, then a third plans again and makes tries 29
# and 30, where the limit stops it. The instance is started once, by the first command; a
# continuation finds it starting (this run's own start) and only waits. The final answer is the
# one-command run's: the same lines of the skills, the start's sentence, the limit's sentence and
# the one item; only the last plan's own line under the table differs (that plan reads the
# instance as starting, not stopped).
# sql operations list is read once per try and once by each continuation's plan (the instance is
# set to run): 30 tries + 2 plans = 32. Responses 1 to 32 say starting; a 33rd read would accept.
