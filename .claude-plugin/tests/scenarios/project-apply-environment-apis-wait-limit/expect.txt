# The GCP project is created and its APIs enabled, but every read of the image repository is refused
# (an API just enabled that is still not on). The run waits 30 seconds and tries the image
# repository's skill again, at most 10 tries in all (9 waits); when the limit passes it stops: status
# updated, nothing after it runs, and no last plan is made (a search after the enable fails in this
# fixture, which would add the item verify). The project was created in this run and a search by
# labels may not show it yet: the item apis names its id and says to wait a minute and run
# project-plan, and to apply again only when that plan shows environment dev as exists; never a
# bare "apply again". The fake's 11th read of the repository answers "not found" (numbered responses:
# calls 1 to 10 get the refusal, the 11th the answer): a run that tried an 11th time would go on to
# create the repository, which the NOT_CALLED below forbids. So the limit is pinned both ways.
CALLED ^services enable .*--project=aleogr-dev-demo-[a-z0-9]{4}( |$)
COUNT 10 ^artifacts repositories describe demo .*--format=json$
COUNT 9 ^sleep 30$
ORDER ^services enable >> ^sleep 30
NOT_CALLED ^artifacts repositories (create|set-cleanup-policies|add-iam-policy-binding)
NOT_CALLED ^iam( |$)
OUTPUT "item": "apis", "reason": "manual", "how": "[^"]*minute
OUTPUT "item": "apis", "reason": "manual", "how": "[^"]*aleogr-dev-demo-[a-z0-9]{4}[^"]*/aleogr:project-plan[^"]*only when[^"]*environment dev[^"]*exists
OUTPUT_NOT "how": "[^"]*/aleogr:project-apply confirm=yes"
OUTPUT "status": "updated"
OUTPUT_NOT "item": "verify"
OUTPUT_NOT nothing to do
OUTPUT_NOT PERMISSION_DENIED|has not been used
NOT_CALLED --method|^gh pr create|^git (switch|add|commit|-c credential)
OUTPUT still refused after 10 tries
# Every wait is exactly sleep 30 (COUNT is "at least"; this keeps other lengths out).
NOT_CALLED ^sleep ([^3]|3[^0]|30.)
