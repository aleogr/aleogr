# was (topic sample), the repository holds the merged one (topics sample and status-page), and the
# pull rewrites the folder's declaration (the folder after/ of this scenario: the fake git copies
# it over the working folder when the pull runs). The run updates the folder, plans again, and
# configures the repository with the NEW topics, built from the declaration as the pull left it,
# then ends nothing to do. Built from the declaration as it was when the command started (the
# defect the real run of part 3a found), the configure is given the old topics, adds none, and
# the run ends asking again for a confirmation already given.
